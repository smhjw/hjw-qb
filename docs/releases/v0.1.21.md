# QBRemote 0.1.21（22）更新说明

## 中文

- 修复卡片拖拽重排的残影与卡顿：拖动层改为固定占位、完全不透明，拖动期间暂停后台刷新。
- 提升主题与界面偏好切换的可靠性：UI 偏好改为独立的单写入队列，快速连续切换以最后一次为准。
- 降低后台耗电：轮询由前台状态门控，应用退到后台时自动停止刷新。
- 对连接故障的服务器采用指数退避重试，避免高频重连触发服务端封禁。
- 新增公网明文连接警示：通过未加密 HTTP 连接公网地址时在服务器设置中提示风险（局域网地址不受影响）。
- 完成通知增加锁屏隐私保护：锁屏上仅显示标题，不再泄露种子名与服务器名。
- 对系统分享传入的文本增加长度与条数上限，防御恶意超大输入。
- 加强构建可复现性与发布校验链：Gradle wrapper 固定校验和、发布产物生成 SHA256 清单、tag 触发的发布工作流交叉核验。
- 目标平台升级至 Android 16（API 36），满足 Google Play 2026-08-31 目标 API 政策。
- 修复首页多服务器卡片长按拖动时其余卡片被遮黑的问题。
- 修复部分 Transmission 服务器无法连接（RPC path not found）：RPC 请求不再跟随重定向、固定使用 HTTP/1.1，并容忍 BOM 前缀的 JSON 响应；连接失败信息现在包含服务器实际返回的内容片段。
- 修复 qBittorrent 4.x 服务器暂停/继续操作失败的问题（stop/start 到 pause/resume 的端点降级此前不可达）。

## English

- Fixed card drag-reorder ghosting and jank: the drag layer now uses a fixed placeholder and is fully opaque, and background refreshes pause while dragging.
- Made theme and UI preference switching reliable: UI preferences now use a dedicated single-writer queue where the latest change wins.
- Reduced background battery drain: polling is gated on foreground state and stops when the app goes to the background.
- Added exponential backoff for failing servers to avoid rapid reconnects triggering server-side bans.
- Added a cleartext-over-public-network warning: server settings now flag unencrypted HTTP connections to public addresses (LAN addresses are unaffected).
- Added lock-screen privacy for completion notifications: only the title is shown on the lock screen, hiding torrent and server names.
- Bounded the length and count of text accepted from the system share sheet to defend against oversized malicious input.
- Strengthened build reproducibility and the release verification chain: pinned Gradle wrapper checksum, SHA256 manifests for release outputs, and a tag-triggered release workflow as a cross-check.
- Raised the target platform to Android 16 (API 36) to satisfy Google Play's 2026-08-31 target API policy.
- Fixed sibling server cards being blacked out while long-press dragging on the home page.
- Fixed some Transmission servers failing to connect (RPC path not found): RPC requests no longer follow redirects, are pinned to HTTP/1.1, and tolerate BOM-prefixed JSON; connection failures now include a snippet of what the server actually returned.
- Fixed pause/resume failing against qBittorrent 4.x servers (the stop/start to pause/resume endpoint fallback was previously unreachable).
