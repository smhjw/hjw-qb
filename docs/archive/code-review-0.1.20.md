# QBRemote 0.1.20 代码审查报告

## 本轮直接清理

- 完整删除“存储压力”卡片、显示模型、待下载量字段、qB/Transmission 专用映射、资源和测试；旧布局中的 `storage_pressure` 仅在迁移测试输入中保留并会被过滤。
- 删除已经没有生产引用的“未知 Tracker 站点”资源；无工作 Tracker 时只使用磁力链接回退或显示“无 Tracker（DHT/PEX）”。
- 去除两处卡片拖动中的 `CompositingStrategy.Offscreen`、拖动态缩放和平台阴影，统一为固定占位与不透明拖动层。
- 将国家数据的公开模型改为 `CountryPeerCountRecord.peerCount`，Peer 快照不再保存无用的上传字节字段。
- 将主题及通用 UI 偏好写入从完整连接配置保存中分离，避免 UI 操作意外改写服务器配置。

## 严谨性改进

- 限速保存后从目标服务器回读并逐字段校验；过期切服请求不会覆盖当前服务器。
- qB 正常上传/下载限速只从 `app/preferences` 的 `up_limit` / `dl_limit` 读取；实时速度和传输信息不会覆盖表单。
- Peer 观察按“日期作用域 + 种子 hash + Peer IP/端口 + 国家”去重，跨日清空，且不提高现有采样频率。
- 主题采用单写入队列与 latest-wins 合并，旧 DataStore 发射不会回滚用户刚选择的主题。
- API、版本、签名及压缩策略都由构建脚本在发布阶段再次核验。

## 有意保留

- `dailyCountryUpload*` 等 DataStore/缓存字段名暂时保留，用于兼容已有安装的数据；其值现在明确表示 Peer 计数。直接重命名会让旧缓存静默丢失。
- `freeSpaceOnDisk` 仍用于服务器摘要卡片，不属于已删除的“存储压力”模块。
- 台湾地区合并到中国热力图的既有展示规则属于产品行为，本轮不擅自改变。

## 仍需实体设备确认

- 自动化测试可以验证手势状态、单一卡片主体及顺序，但 OLED/高刷新率设备上的主观残影观感仍需实体机确认。
- 无边框布局可通过编译、Lint 和模拟器/设备测试验证；若当前环境没有 API 26/35/36 设备，只能明确标记为待设备验证，不能视为已完成真机验收。
